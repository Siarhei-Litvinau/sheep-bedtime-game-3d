# Овцы перед сном

3D relaxing/bedtime-игра на Three.js для Яндекс Игр. Вся геометрия сцены собирается процедурно из примитивов (`BoxGeometry`, `SphereGeometry`, `ConeGeometry`, `CylinderGeometry`) — никаких внешних `.fbx`/`.glb`. Анимации — ручная интерполяция во времени внутри `requestAnimationFrame`, без скелетной анимации.

**Полное техническое задание**: `claude-code-prompt-sheep-game.md` — если меняешь механику/тайминги/палитру, сверяйся с ним, там всё пронумеровано по разделам (например «раздел 5.1», «раздел 6»), и код ссылается на эти номера в комментариях.

## Статус

Все 14 пунктов раздела 11 (порядок реализации) готовы и вручную проверены в браузере (см. «Как проверять» ниже — рендер зависит от фокуса вкладки).

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173, hot reload
npm run build    # → dist/, относительные пути (base: './'), можно открыть с любого поддиректория
npm run preview  # локально проверить прод-сборку
```

Деплой на GitHub Pages настроен через `.github/workflows/deploy-pages.yml` (пуш в `master` → билд → `actions/deploy-pages`). **Один раз вручную нужно**: в настройках репозитория GitHub → Settings → Pages → Source → выставить «GitHub Actions» (сам workflow этого сделать не может).

## Архитектура

```
src/
  main.js                  — сборка сцены, игровой цикл, стартовый экран (startGame() запускается по клику)
  core/                    — renderer, camera, lighting: голая инфраструктура Three.js, без игровой логики
  world/                   — статические/полу-статические объекты сцены (см. таблицу ниже)
  game/                    — управляющая логика сессии (стейт-машины, кривые, очередь)
  effects/                 — короткоживущие партиклы (искры, ZZZ)
  audio/AudioManager.js    — звук: Web Audio API, sfx/music шины, без внешних зависимостей
  platform/yandex.js       — обёртка над SDK Яндекс Игр, безопасный no-op вне платформы
store-assets/              — icon.svg / cover.svg для карточки игры на Яндекс Играх (не используются в рантайме)
public/favicon.svg         — копия иконки, реально отдаётся как фавикон
public/audio/              — реальные звуковые файлы, которые грузит игра (см. ниже)
assets/audio/              — исходники скачивания (audio-download-prompt.md) и файл лицензии Kenney;
                              НЕ используется рантаймом напрямую — Vite отдаёт как есть только public/
```

### Файлы `world/` — что за чем

| Файл | Роль | Раздел ТЗ |
|---|---|---|
| `surface.js` | `createSurfaceSampler(planet)` даёt точку+нормаль на сфере планеты по (x,z); `orientUpForward`/`orientAlongTangent` строят кватернион, ставящий объект перпендикулярно кривизне. **Используется почти всеми world-объектами** — если добавляешь новый объект на землю, бери отсюда. | 5.10 |
| `Planet.js` | Сфера с кастомным unlit-шейдером: две половины (день/ночь) через `uDayDir`/`uSoftness`, `setColors()`/`setTerminatorAngle()` дёргает `SessionColorCurve` каждый кадр. | 5.10 |
| `Fence.js` | Инстансированный забор (столбы+жерди), идёт **поперёк экрана вдоль X** на `z=4`, пересекает границу день/ночь по центру. (Первая попытка — забор вдоль Z — читалась как палка, см. историю коммитов/чат.) | 5.6 |
| `Sheep.js` | Геометрия одной овцы. **Оптимизировано**: тело+хвост слиты в один меш (двигается вместе при squash/stretch), уши+ноги слиты в статичный меш, голова отдельно (анимируется независимо). 3 draw call вместо 8. | 5.1, раздел 8 |
| `Barn.js` | Амбар с сеткой окон; `lightNextWindow()` зажигает следующее тёмное окно через `emissive`-переход. Окна на `MeshLambertMaterial`, не `MeshBasicMaterial` — иначе «выключенное» окно светлее реально освещённого сценой фасада. | 5.5 |
| `Vegetation.js` | Деревья+трава, инстансированные, покачивание с шарниром у земли (не у центра геометрии!), синхронно с текущим cpm дыхательного цикла. | 5.7 |
| `Stars.js` | `THREE.Points` + кастомный шейдер, мерцание завязано на cpm с случайной фазой на звезду. | 5.9 |
| `BackgroundClouds.js` | Декоративные (не NPC) облака-блобы, статичные, инстансированные. | 5.8 |
| `OwlFirefly.js`, `Cat.js`, `CloudNpc.js` | Три тап-NPC, каждый — своя мини-стейт-машина. Тап определяется raycasting'ом в `main.js` (`tryTapNpc`), **до** старта заряда прыжка овцы — если тап попал в NPC, заряд не стартует. | 5.2–5.4 |

### Файлы `game/` — управляющая логика

| Файл | Роль |
|---|---|
| `sheepCount.js` | Число овец = f(длительность сессии), кусочно-линейная интерполяция по опорным точкам (5→6, 10→8, 12→12, 18→15). Отклонение от ТЗ: не хардкодит промежутки, а выводит их из длительности. |
| `BreathingCycle.js` | Кривая замедления дыхания 12–15→6 cpm. **Отклонение от буквального текста ТЗ**: интервал между шагами не фиксирован «~2 мин», а вычисляется как `sessionDuration / totalSteps` — иначе по буквальным цифрам ТЗ полная 18-минутная сессия не успевала бы дойти до финальных 6 cpm (нужно ~30 мин). Так кривая гарантированно доходит до финала к концу **любой** выбранной сессии. |
| `SheepAnimator.js` | Стейт-машина одной овцы: `approach→idle→charge→jump→land→walk→yawn→fade→done`. `approach` — овца сама медленно идёт от точки выпаса (`graze`) к забору (`start`); `startCharge()` — no-op, пока не дойдёт и не перейдёт в `idle` (см. её guard). Тап засчитывается только рядом с активной овцой (`isNearActiveSheep` в `main.js`, экранный радиус). Темп фаз и частота idle-покачивания берутся из `BreathingCycle` через `setCyclePace()`/`setBreathingCpm()` каждый кадр. Без `callbacks.onComplete` зацикливается сама на `idle` — использовалось для точечного тестирования до появления очереди. |
| `SheepQueue.js` | N овец, активна всегда только первая (совпадает с фактическим `SheepAnimator`), остальные — статичный компактный строй у точки выпаса `graze` (ряды по 3, не длинная цепочка — иначе выезжают за камеру/за спину). |
| `CameraRig.js` | Камера — конечный автомат из 4 состояний (`FLOCK_VIEW`/`SHEEP_SELECTED`/`JUMP_CINEMATIC`/`RETURN_TO_FLOCK`), `update()` каждый кадр экспоненциально подтягивает реальную позицию/цель к «желаемой» для текущего состояния (плавный tween без ключевых кадров). Маппинг `cameraStateForSheepPhase(animatorState)`: приближается **только** на `charge`/`jump` (`SHEEP_SELECTED`/`JUMP_CINEMATIC`), сразу отъезжает обратно на `land` (`RETURN_TO_FLOCK`) — не ждёт `fade`. `JUMP_CINEMATIC` держит тот же ракурс (позади+сверху овцы), что и `SHEEP_SELECTED`, с лёгким zoom-out на пике дуги прыжка (тот же колокол `4·t·(1-t)`, что задаёт высоту дуги в `SheepAnimator._updateJump`) — **специально не уводит камеру в профильный вид сбоку**: первая версия делала это через большой офсет по `side`, читалось как «камера едет вправо», а не как слежение за овцой. `core/camera.js` задаёт только стартовую позицию (значение для `FLOCK_VIEW`), реальным управлением по кадрам занимается этот файл, вызывается из `main.js` → `tick()`. |
| `SessionColorCurve.js` | Яркость/цвет/позиция терминатора планеты = f(прогресс сессии). |
| `responseIntensity.js` | Множитель силы свечения+искр (угасающий отклик), 1.0→0.35. |
| `SessionFade.js` | DOM-оверлей (`#fade-overlay`), 7 сек, независим от WebGL-рендера. |

### Звук — `src/audio/AudioManager.js`

Web Audio API напрямую (без Howler.js — не за чем добавлять зависимость ради пары gain-нод). Два бас: sfx (потолок 60% громкости, привязан к `responseIntensityAt(progress)` — той же угасающей кривой отклика, что двигает свечение/искры) и music (зациклённый фоновый трек, громкость привязана к прогрессу сессии — та же кривая яркости, что и `SessionColorCurve`, плюс отдельный `fadeOut()` на `onSessionComplete`). `unlock()` создаёт `AudioContext` и должен вызываться синхронно из пользовательского жеста — вызывается в начале `startGame()`, которая сама всегда запускается из клика по кнопке стартового экрана.

**Мобильный автоплей**: desktop-браузеры разблокируют `AudioContext` одним `resume()`, но мобильные (особенно iOS Safari) заметно строже — надёжно срабатывает только реальный playback, запущенный синхронно внутри жеста, поэтому `unlock()` сразу проигрывает тишину (`createBuffer(1,1,...)` + `start(0)`), а не просто вызывает `resume()`. Плюс мобильные ОС усыпляют уже разбуженный контекст при блокировке экрана/уходе приложения в фон — `AudioManager.resume()` (no-op, если и так `running`) вызывается на каждом `pointerdown` по канвасу и на `visibilitychange` (`main.js`), чтобы это не приводило к молчащему звуку до следующей полной перезагрузки страницы. Никогда не тестировалось на реальном мобильном устройстве (см. «Известные ограничения» ниже) — если звука всё ещё нет на телефоне после этого фикса, смотреть `window.__debug.audio.context.state` через удалённый девтулз (`chrome://inspect` для Android, Web Inspector для iOS).

Файлы читаются из `public/audio/` (не `assets/audio/` — это просто папка-источник скачивания из `audio-download-prompt.md`, Vite её не бандлит). Загрузка каждого файла — `fetch` + `decodeAudioData` в `try/catch`: если файла нет или он не декодируется, звук молча пропускается (`buffers.get(key)` вернёт `null`), без ошибок в рантайме. Один файл всё ещё требует ручного скачивания с Pixabay (`sheep_bleat.mp3` — раздел 4 промта, прямых ссылок для автоскачивания нет); до тех пор, пока его нет в `public/audio/`, звук приземления беззвучен — весь остальной звук, включая фоновую музыку, уже работает.

Таблица событий → звук (полная — `audio-download-prompt.md`, раздел 3) реализована в `main.js`: тап/заряд и отпускание/прыжок овцы (`pointerdown`/`pointerup`, `tap_soft.mp3`, у прыжка выше питч), приземление (`onLand` в `SheepQueue`→`SheepAnimator`, `sheep_bleat.mp3`), окно амбара (`onWindowLit`, приглушённый `tap_soft.mp3`), тапы по NPC (сова → `owl_hoot.mp3`, кот → зацикленный на ~2.5с `cat_purr.mp3`, облако → `tap_gentle.mp3`, второй мягкий клик из Kenney-пака — выбран `pluck_002.ogg`, самый тихий/округлый среди `pluck`/`click`/`tick`/`select` по замеру `ffmpeg -af volumedetect`), завершение сессии (`onSessionComplete` → `audio.fadeOut()`).

### `main.js` — как это всё связано

`wireStartScreen()` вешает обработчики на кнопки старта → `startGame(sessionDurationMinutes)` создаёт **всю** сцену с нуля (ничего не собирается до выбора длительности). Внутри `startGame`: raycasting для NPC, pointer-события для заряда/прыжка (взаимно исключающие с NPC-тапом), кнопка паузы (гейтит весь `tick()` кроме рендера), и сам `tick()` — единая точка, где каждый кадр читаются `breathingCycle`/`colorCurve`/`responseIntensity` и раздаются во все системы.

**`window.__debug`** (только `import.meta.env.DEV`) — там лежат ссылки на все системы (`sheepQueue`, `barn`, `colorCurve`, `renderer`, `forceRender()` и т.д.). Полезно для отладки без пересборки — см. «Как проверять».

## Ключевые константы (где крутить, если просят «сделай длиннее/короче/ярче»)

- Длительность сессии по умолчанию сейчас выбирается на стартовом экране (`main.js` → `wireStartScreen`), диапазоны `begin(5,10)` / `begin(12,18)`.
- Тайминги фаз прыжка — `SheepAnimator.js`, константы вверху файла (`LAND_DURATION`, `WALK_DURATION`, `YAWN_DURATION`, `FADE_DURATION`, `MAX_CHARGE`, `APPROACH_DURATION`).
- Высота и длительность самого прыжка — **не константы**, а формулы в `SheepAnimator.release()`: `jumpHeight = 0.9 + chargeT * 1.3` (0.9–2.2, чем дольше держать заряд — тем выше), `jumpDuration = 0.85 + chargeT * 0.85` (0.85–1.7с). Нижняя граница высоты (0.9) не понижена ниже верхней жерди забора (`Fence.js` → `RAIL_HEIGHTS`, 0.68) — иначе на коротком тапе овца казалась бы проходящей сквозь забор, а не перепрыгивающей его.
- Приближение/отъезд камеры — офсеты по `forward`/`side`/`up` в `CameraRig.js`, case'ы `SHEEP_SELECTED`/`JUMP_CINEMATIC` внутри `update()`. Если просят «камеру ближе/дальше» — крутить именно эти коэффициенты, не тайминги сглаживания (`POS_SMOOTH`/`LOOK_SMOOTH` вверху файла — это скорость, с которой камера **догоняет** желаемую позицию, а не сама позиция).
- Радиус тапа по овце — `SHEEP_TAP_RADIUS_PX` в `main.js` (сейчас 100px), точка выпаса/старта овцы — `waypoints.graze`/`waypoints.start` там же.
- Расстановка забора/амбара/деревьев/NPC — все координаты живут прямо в `main.js` (не вынесены в конфиг, т.к. это одноразовая ручная композиция сцены).
- Портретный FOV (насколько «раскрывается» общий план на узких экранах) — `BASE_FOV`/`REFERENCE_ASPECT`/`MAX_FOV` в `core/camera.js` → `fovForAspect()`. Если на портретном экране всё ещё обрезает отару/амбар по бокам — поднимать `MAX_FOV` там же (сейчас 90°); близкие ракурсы (`SHEEP_SELECTED`/`JUMP_CINEMATIC`) на это не реагируют — у них свой фиксированный `CLOSE_UP_FOV`, см. `CameraRig.update()`.

## Как проверять изменения

**Важно**: в headless/автоматизированном Chrome (через MCP claude-in-chrome) вкладка часто оказывается вне фокуса, а Chrome **полностью останавливает `requestAnimationFrame`** для скрытых вкладок — это нормальное поведение браузера, не баг игры. Поэтому:

1. Для проверки **логики** (тайминги стейт-машин, переходы) — дёргай `update(dt)` напрямую через `window.__debug` в консоли (`javascript_exec`), не полагаясь на реальное время/rAF. Пример — прогнать всю очередь до конца (каждая овца сначала сама идёт от `graze` к забору — `startCharge()` не сработает, пока она не дойдёт до `idle`, отсюда прогон `approach` перед зарядом):
   ```js
   const d = window.__debug, q = d.sheepQueue, barn = d.barn;
   function runOneCycle() {
     for (let i=0;i<200 && q.animator.state === 'approach';i++){ q.update(0.05); barn.update(0.05); }
     q.animator.startCharge();
     for (let i=0;i<10;i++){ q.update(0.05); barn.update(0.05); }
     q.animator.release();
     for (let i=0;i<900 && q.animator;i++){ q.update(0.02); barn.update(0.02); }
   }
   for (let i=0;i<d.sheepCount;i++) runOneCycle();
   ```
2. Для проверки **визуала** — `d.forceRender()` после ручных правок стейта форсирует один кадр рендера в обход rAF, затем `screenshot`/`zoom`.
3. Числа/цвета сравнивай через `renderer.info.render.calls/triangles` (перф) и прямое чтение `.getHexString()` на материалах — не полагайся на глаз в сжатом JPEG-скриншоте, он врёт по яркости (проверено на кривой раздела 6 — разница была огромной в пикселях, но малозаметной на глаз).

## Известные ограничения / не сделано

- **Раздел 13 «тест на мобильном»**: реального устройства всё ещё не было, `resize_window` в этом окружении не меняет `window.innerWidth`/`innerHeight` (ограничение автоматизации chrome-инструмента, не проекта) — портретная адаптация проверена подстановкой размеров канваса/камеры напрямую через `window.__debug` (не настоящим ресайзом окна). Что сделано:
  - **Портретный FOV** (`core/camera.js` → `fovForAspect()`): на узких экранах (aspect < 16:9) вертикальный FOV общего плана растёт до `MAX_FOV=90°`, иначе на портретных телефонах отара/забор/амбар обрезались по бокам (при фиксированном 50° на aspect≈0.46 отара уходила за кадр полностью — проверено). **Не** применяется к close-up ракурсам `CameraRig` (`SHEEP_SELECTED`/`JUMP_CINEMATIC`, см. `CLOSE_UP_FOV`) — тот же рост FOV там даёт заметный fisheye на траве/деревьях вплотную к объективу и ломает заранее подобранную композицию; `CameraRig.update()` сам решает, каким FOV пользоваться, по состоянию, и плавно интерполирует его при смене (`FOV_SMOOTH`), как позицию/цель взгляда.
  - **Мобильный long-press без системного поиска**: игра держится на press-and-hold (заряд прыжка) — без обработки это триггерит на телефоне выделение текста и системный попап "Найти"/"Copy"/"Look Up". Исправлено: `user-select`/`-webkit-touch-callout: none` глобально в `style.css`, плюс `document.addEventListener('contextmenu', …)` в `main.js` как подстраховка.
  - **Мобильный автоплей аудио**: пользователь сообщил, что после первого прохода мобильной адаптации звука на телефоне не было вообще (ни музыки, ни sfx) — почти наверняка стандартная строгость мобильных браузеров к `AudioContext.resume()` (см. «Мобильный автоплей» в разделе про `AudioManager` выше: тишина-в-жесте + повторный `resume()` на каждом тапе/`visibilitychange`). Тоже не проверено на реальном устройстве — если после этого фикса звука всё ещё нет, читать `window.__debug.audio.context.state` через удалённый девтулз.
  - Размеры кнопок (≥44×44px) и `safe-area-inset-*` — было подтверждено раньше, актуально по-прежнему.
- **Аудио**: реализовано по `audio-download-prompt.md` (см. `src/audio/AudioManager.js` выше). Фоновая музыка подключена (`public/audio/background_ambient.mp3` — «Sleep Music» автора Leberch, Pixabay, транскодирован в 128 kbps из исходных 256 kbps/28.6MB, исходник — `assets/audio/leberch-sleep-music-587996.mp3`). Единственный оставшийся пробел — `public/audio/sheep_bleat.mp3` (звук приземления), требует ручного скачивания с Pixabay (`audio-download-prompt.md`, раздел 4); до тех пор это одно событие беззвучно, весь остальной звук работает.
- **Реклама Яндекс Игр**: подключён только липкий баннер (`showStickyBanner` в `platform/yandex.js`), полноэкранная/interstitial между сессиями осознанно не добавлена — конфликтует с целью «снижение возбуждения перед сном» (раздел 1). Если продакт передумает — там же и добавлять.
- **Иконка/обложка** (`store-assets/`) — SVG-источники, процедурная векторная графика в стиле проекта, не финальный растровый PNG под конкретные требования Яндекс Игр по пикселям — при загрузке в консоль разработчика может понадобиться экспорт в PNG нужного размера.
- Бандл ~520KB (в основном сам Three.js) — vite ругается на chunk size warning, осознанно не code-splitting, не критично для одностраничной игры.
- **Доворот планеты вслед за движением овцы** (раздел 4 ТЗ упоминает это как опционально, «можно») — не реализован. Потребовал бы либо общего `THREE.Group` на всю сцену (сейчас `planet`/`fence`/`barn`/`vegetation`/`stars`/... добавляются в `scene` по отдельности в `main.js`), либо вращения самой камеры по дуге вокруг центра планеты — обе опции самостоятельная задача сверх текущего слежения `CameraRig` за овцой, которое и так полностью решает задачу «камера видит овцу».
