# ПРОМТ ДЛЯ CLAUDE CODE: "Овцы перед сном" — 3D bedtime-игра для Яндекс Игр

Это полное техническое задание на генерацию проекта. Вставь этот файл в Claude Code как основной контекст и попроси реализовать проект по разделам ниже. Вся 3D-геометрия создаётся процедурно в коде (без внешних .fbx/.glb моделей) — это ключевое архитектурное решение.

---

## 0. Инструкция для Claude Code при старте работы

> Создай веб-игру на Three.js (WebGL) для платформы Яндекс Игры. Вся геометрия сцены (овцы, забор, амбар, деревья, облака, NPC) собирается процедурно из примитивов Three.js (BoxGeometry, SphereGeometry, ConeGeometry, CylinderGeometry и их комбинаций) — не используй внешние 3D-файлы. Анимации реализуй через изменение позиции/масштаба/поворота во времени (например, через встроенный Tween или ручную интерполяцию в requestAnimationFrame), без скелетной анимации/риггинга. Следуй техническим параметрам, цветовой палитре, полигональным бюджетам и структуре анимаций, описанным в разделах ниже, точно как указано. Начни с базовой сцены (планета, забор, одна овца, базовый цикл прыжка), затем добавляй остальные элементы по порядку разделов.

**Рекомендуемый стек**: Three.js (лёгкий, хорошо документирован, прямой экспорт под HTML5/Яндекс Игры, никаких лишних зависимостей). Если у вас уже есть предпочтение по движку (Godot/Phaser/Construct) — скажите, вся геометрия ниже адаптируется под примитивы соответствующего движка.

## 1. Концепция игры

Круглая планета-сюрреализм, разделённая на две половины: тёплые сумерки с одной стороны, ночь со звёздами — с другой. Игрок помогает сонным овцам одна за другой перепрыгнуть через забор из светлой половины в тёмную, где они уходят спать в амбар. По ходу сессии солнце смещается, экран темнеет, ритм замедляется, стадо тает, амбар "наполняется" спящими овцами. Финал — последняя овца засыпает, сцена сама плавно гаснет.

Жанр: relaxing / bedtime. Цель — снижение возбуждения игрока, а не вовлечённость.

---

## 2. Научное обоснование (кратко, для контекста дизайна)

- Дыхание ~6 циклов/мин (0.1 Гц) максимизирует HRV через барорефлекторный резонанс — подтверждено РКИ (n=112, n=96, n=88).
- Музыкальный темп 60–80 BPM даёт наибольший релаксирующий эффект (синтез 3 метаанализов).
- Насыщенность и яркость цвета — главные драйверы физиологического возбуждения, важнее оттенка (n=62, n=64); красный спектр — самый возбуждающий.
- Синий свет экрана подавляет мелатонин; важна общая яркость, не только цветовая температура.

Полное обоснование с источниками — см. предыдущий документ `bedtime-3d-game-spec.md` / `sheep-bedtime-game-full-spec.md`, если он тоже загружен в проект.

## 3. Числовая спецификация ритма (обязательна к точной реализации)

```
СТАРТОВАЯ СКОРОСТЬ ЦИКЛА:      12–15 циклов/мин (цикл 4–5 сек)
ШАГ ЗАМЕДЛЕНИЯ:                −0.5 цикла/мин
ДЛИТЕЛЬНОСТЬ ШАГА:             ~2 минуты
ФИНАЛЬНАЯ СКОРОСТЬ:            6 циклов/мин (цикл 10 сек)
НАПРАВЛЕНИЕ:                   только замедление, без ускорений/колебаний назад

ЧИСЛО ОВЕЦ = функция от длительности сессии:
  короткая сессия (5–10 мин)  → 6–8 овец
  полная сессия (12–18 мин)   → 12–15 овец
```

Реализовать как параметризуемую кривую (массив шагов скорости по времени), не хардкодить фиксированные тайминги — длительность сессии должна быть настраиваемым параметром при старте игры.

## 4. Игровая механика

**Взаимодействие**: удержание пальца/кнопки мыши = вдох (овца заряжается разбегом), отпускание = выдох/прыжок. Без требований к точности тайминга. Чем дольше держит игрок — тем плавнее анимация разбега.

**Цикл прыжка** (4 фазы, привязаны к текущей скорости цикла из раздела 3):
1. Разбег (вдох/удержание) — нарастание энергии, лёгкое свечение
2. Прыжок/зависание (пик) — звёздная пыльца, самая "невесомая" точка
3. Приземление (спад/отпускание) — плавное замедление
4. Уход в амбар — 2–3 стадии затухания движения → скрывается за дверью

**Индикация прогресса**: без цифр/счётчиков. Окна амбара — по одному загораются тёплым светом на каждую заснувшую овцу. Редкие ZZZ над крышей как вторичный акцент.

**3 фоновых NPC** (опциональны, без таймера): сова/светлячок (тап гасит свечение поэтапно), кот (тап → сворачивается клубком, разовая анимация), облако (тап → опускается и замедляется, к финалу зависает над амбаром).

**Угасающий отклик**: визуальный/звуковой фидбек на действия игрока становится тише и мягче по ходу сессии.

**Завершение**: после последней овцы — автоматическое плавное затемнение, без ожидания игрока.

## 5. Процедурные 3D-брифы по объектам

Для каждого объекта: роль, силуэт, сборка из примитивов, палитра, полигональный бюджет, список состояний анимации.

### 5.1 Овца (главный объект)

**Роль**: центральный, несёт основной дыхательный ритм сцены.
**Силуэт**: узнаваема по компактному круглому телу на низких тонких ножках — должна читаться единым пятном даже без деталей морды.
**Сборка из примитивов**:
- Тело — `SphereGeometry` (слегка сплющенная по Y, scale.y ≈ 0.85) или `CapsuleGeometry`
- Голова — меньшая `SphereGeometry`, тёмный оттенок (мордочка), присоединена спереди-сверху
- Уши — 2× плоский `ConeGeometry` или `PlaneGeometry`, по бокам головы
- Ноги — 4× тонкий `CylinderGeometry`, тёмный оттенок
- Хвост — маленький `SphereGeometry`
- (опционально) "кудрявость" шерсти — несколько мелких сфер, налепленных на основное тело, ИЛИ просто shader/noise-текстура на теле для экономии полигонов
**Палитра**: тело — тёплый нейтральный кремовый/светло-серый (низкая насыщенность), морда/ноги — тёмно-коричневый/графитовый, к финалу сессии тело чуть тускнеет вместе с общей цветовой кривой.
**Полигональный бюджет**: 2000–4000 треугольников (ключевой объект по спеке).
**Состояния анимации**:
1. `idle` — стоит у забора, лёгкое покачивание в такт фоновому дыхательному ритму
2. `charge` (разбег/вдох) — приседание, нарастающее лёгкое свечение контура, длительность = длительность удержания игрока
3. `jump` (прыжок/зависание) — дуга по Y с растяжением тела по вертикали в момент пика, частицы звёздной пыли вокруг
4. `land` — сжатие тела при приземлении (squash), плавное гашение
5. `walk_sleepy` — 2–3 замедляющихся цикла ходьбы к амбару, с наклоном головы
6. `yawn` — короткая анимация в конце walk_sleepy перед скрытием за дверью

### 5.2 NPC 1 — Сова / светлячок на ветке

**Роль**: второстепенный, фоновая опциональная активность.
**Силуэт**: компактный круглый силуэт на ветке, легко считывается на фоне.
**Сборка**: тело — `SphereGeometry`, глаза — 2× маленькая сфера ярче основного тона (или emissive-материал для свечения), ветка — тонкий `CylinderGeometry`.
**Палитра**: приглушённый тёплый охра/коричневый, глаза светятся мягким жёлтым (emissive, но не ярким — согласовано с общей низкой насыщенностью).
**Полигональный бюджет**: 500–1000 треугольников.
**Состояния**: `idle_glow` (ровное свечение) → на тап → `dim_1` → `dim_2` → `dim_3` (глаза закрываются, свечение гаснет поэтапно).

### 5.3 NPC 2 — Кот

**Роль**: второстепенный, разовая анимация на тап.
**Силуэт**: сидящий кот с характерным треугольным силуэтом ушей.
**Сборка**: тело — `SphereGeometry`, голова — сфера меньше, уши — 2× `ConeGeometry`, хвост — изогнутый `CylinderGeometry` или serия сегментов.
**Палитра**: тёмный графитовый/тёмно-фиолетовый (хорошо впишется в тёмную половину сцены), без ярких пятен.
**Полигональный бюджет**: 500–1000 треугольников.
**Состояния**: `sitting` (idle) → на тап → `curl_1` → `curl_2` (сворачивается в клубок) → `sleeping` (лёгкое покачивание/дыхание клубка).

### 5.4 NPC 3 — Облако с "зевающим" лицом

**Роль**: второстепенный, движется по небу независимо от основного ритма (намеренный контрапункт).
**Силуэт**: мягкий, округлый, узнаваем как облако силуэтом без текстуры.
**Сборка**: группа из 4–6 пересекающихся `SphereGeometry` разного размера, простое лицо — 2 точки-глаза и дуга-рот из тонких примитивов или текстуры.
**Палитра**: светлый нейтральный, полупрозрачный (opacity 0.85–0.95), на тёмной половине неба слегка теплее по тону, чем звёзды вокруг.
**Полигональный бюджет**: 300–600 треугольников.
**Состояния**: `drift` (движение по небу, независимая скорость) → на тап → `yawn` (короткая анимация) → `lower_slow` (опускается ниже и замедляется) → к финалу сессии `rest_over_barn` (зависает статично над амбаром).

### 5.5 Амбар

**Роль**: конечная точка, индикатор прогресса.
**Силуэт**: простой домик — прямоугольное тело + треугольная крыша, максимально узнаваем.
**Сборка**: корпус — `BoxGeometry`, крыша — `ConeGeometry` (4 сегмента, чтобы дать форму двускатной крыши) или сплющенный `BoxGeometry`, дверь — плоскость/тёмный `BoxGeometry` на фасаде, окна — набор маленьких `PlaneGeometry`/`BoxGeometry` с emissive-материалом (изначально выключены/тусклые).
**Палитра**: тёплое дерево (приглушённый коричнево-красный, НЕ насыщенный красный), крыша темнее корпуса.
**Полигональный бюджет**: 1500–3000 треугольников.
**Состояния**: `window_off` × N → по одному переключаются в `window_on` (тёплый emissive) с каждой заснувшей овцой; редкий `zzz_pulse` — партиклы/спрайты над крышей.

### 5.6 Забор

**Роль**: статичный композиционный якорь, задаёт линию горизонта.
**Силуэт**: горизонтальная повторяющаяся структура, не должна визуально соперничать с овцами.
**Сборка**: набор `CylinderGeometry` (столбы) + `BoxGeometry` (горизонтальные жерди), инстансированные (`InstancedMesh`) для экономии draw calls.
**Палитра**: тёмное дерево, низкая насыщенность, не выделяется на фоне.
**Полигональный бюджет**: 200–400 треугольников на секцию, переиспользуется через инстансинг.
**Состояния**: полностью статичен, анимации нет.

### 5.7 Деревья и трава (фон)

**Роль**: фоновый, малозначимый, лёгкое покачивание в такт основному ритму.
**Сборка**: деревья — `CylinderGeometry` (ствол) + `ConeGeometry`/сплющенная `SphereGeometry` (крона); трава — упрощённо, либо низкополигональные плоскости-пучки (`PlaneGeometry`), либо инстансированные тонкие конусы.
**Палитра**: приглушённый зелёный/оливковый на светлой половине, тёмный сине-зелёный на тёмной.
**Полигональный бюджет**: до 500 треугольников на объект, максимальное переиспользование через инстансинг.
**Состояния**: `sway` — лёгкое покачивание амплитудой ~2–3°, синхронно с текущей скоростью дыхательного цикла (не независимо).

### 5.8 Облака фона (не NPC, декоративные)

Такая же сборка, как NPC 3, но без лица и интерактивности, меньший полигональный бюджет (150–300), инстансируются для заполнения неба.

### 5.9 Звёзды

**Сборка**: не геометрия, а `Points`/партикл-система (`THREE.Points`) с точечным материалом — сотни звёзд одним draw call.
**Поведение**: мерцание яркости (opacity/size) синхронно с дыхательным циклом, очень мягкая амплитуда (вторичный слой, не основной ритм).
**Полигональный бюджет**: не применим (point cloud, не меши) — это самый дешёвый способ дать много звёзд без нагрузки на draw calls.

### 5.10 Планета/горизонт

**Сборка**: `SphereGeometry` большого радиуса (камера видит только верхний сегмент как изогнутый горизонт) ИЛИ упрощённо — изогнутая плоскость (`PlaneGeometry` с деформацией вершин по дуге) для экономии полигонов, если полная сфера избыточна.
**Материал**: градиент через vertex colors или shader — тёплый на светлой половине, холодный приглушённый на тёмной, с плавным переходом посередине (терминатор дня/ночи).
**Полигональный бюджет**: до 1000 треугольников — это фон, детализация не нужна.

## 6. Цветовая и световая кривая сессии

Реализовать как функцию от прогресса сессии (0.0 → 1.0), обновляющую в реальном времени:

```
БРЯКОСТЬ СЦЕНЫ (общий multiplier):     1.0 → 0.5  (плавное снижение)
НАСЫЩЕННОСТЬ ПАЛИТРЫ:                  умеренная → низкая
ЦВЕТОВАЯ ТЕМПЕРАТУРА (светлая сторона): тёплая → ещё теплее (ниже Кельвин)
ЦВЕТОВАЯ ТЕМПЕРАТУРА (тёмная сторона):  приглушённая холодная, БЕЗ ярко-синего
ПОЗИЦИЯ "СОЛНЦА"/ГРАНИЦЫ ДЕНЬ-НОЧЬ:     смещается по дуге планеты синхронно с прогрессом
```

Красный спектр исключить из палитры полностью, кроме, возможно, самых тёплых оттенков заката (оранжево-розовый) на границе день/ночь в начале сессии.

## 7. Освещение сцены

- Один направленный источник света (имитация солнца/луны) + мягкий ambient/fill light.
- Baked/статичные тени там, где возможно — сцена в основном статична, кроме анимированных объектов.
- Toon-shading или flat-material подход вместо PBR — лучше читается на маленьком экране, дешевле по производительности.

---

## 8. Производительность

- Максимально использовать `InstancedMesh` для повторяющихся объектов (жерди забора, трава, деревья, облака фона).
- Объединять статичную геометрию в единый меш где возможно (merge geometries).
- Текстуры: 512×512–1024×1024, только там, где действительно нужны (не для процедурных primitive-объектов с flat-цветом — там текстуры не нужны вовсе, только material.color).
- Звёзды через `Points`, не через отдельные меши.
- Тестировать на среднем мобильном устройстве по ходу разработки, не только в браузере на ПК.

## 9. UI

- Минимальный: без счётчиков/цифр в основной сцене.
- Экран выбора длительности сессии перед стартом (короткая/полная) — крупные кнопки, ≥44×44px.
- Никакого HUD поверх игрового процесса, кроме, возможно, едва заметной кнопки паузы/выхода в углу.

## 10. Требования платформы Яндекс Игры

- Интеграция SDK Яндекс Игр (авторизация, реклама, если применимо — согласно официальной документации разработчика).
- Иконка: строго квадратная, без скруглений, самостоятельный арт (не скриншот) — например, силуэт прыгающей овцы на фоне звёзд.
- Обложка: художественно скомпонована, читаема в уменьшенном виде.
- Адаптивный layout под разные соотношения сторон (мобильные вертикальные, десктоп горизонтальные).
- Поддержка тач- и мышь/клавиатура-ввода для механики удержание/отпускание.
- Все платежи и авторизация — только через SDK Яндекс Игр.
