## Что именно изменено в пункте 1 (для справки, если понадобится ревью/откат)

Все правки — по сути зеркальное отражение сцены по оси X (было day=+x/night=-x, стало day=-x/night=+x):

- `src/game/SessionColorCurve.js` — `TERMINATOR_ANGLE_START/END` теперь `Math.PI`/`Math.PI+0.3` (uDayDir указывает на -x); добавлен отдельный `SUN_ANGLE_START/END` (0/-0.3, как раньше) для вращения `SUN_BASE_DIR`, который теперь `(-14,16,6)`. Специально разделено на два угла — угол терминатора (`uDayDir`, прямая формула `(cosθ,sinθ)`) и угол поворота солнца (`Ry(θ)` вокруг фиксированного вектора) математически не эквивалентны, наивная замена одного числа на другое дала бы неверный результат.
- `src/core/lighting.js` — стартовая позиция `sun.position` (-14 вместо 14), не влияет на рантайм (перезаписывается `colorCurve.update(0)`), но для консистентности кода.
- `src/main.js` — `planet.setTerminatorAngle(Math.PI)` (тоже перезаписывается colorCurve, чисто для консистентности); барн переставлен на `x=5.0` с `forwardHint (-1,0,1)`; все деревья/трава/фоновые облака/NPC (owl, cat, cloudNpc) зеркально отражены по x; waypoints овцы (`start/land/walkTo`) отражены по x.
- `src/game/SheepQueue.js` — facing-вектор овец в очереди ожидания `(0.3,0,-1)` вместо `(-0.3,0,-1)` (тоже зеркалирование).
- `SheepAnimator.js`, `Fence.js`, `Barn.js` (кроме placement-вызова) трогать не пришлось — они уже геометрически нейтральны к стороне (работают через переданные waypoints/forwardHint).

## Что именно изменено в пункте 2 (для справки, если понадобится ревью/откат)

Радиус планеты и все x/z-координаты композиции раздвинуты (примерно в 1.4–2× по разным осям, барн — сильнее остальных), плюс подтянуты тайминги/дистанции анимации, которые были жёстко завязаны на старые расстояния:

- `src/world/Planet.js` — радиус по умолчанию 30 → 46. Формула позиции меша (`y = -radius + 3`) уже была параметризована радиусом, отдельно трогать не пришлось.
- `src/main.js`:
  - `scene.fog`: `(25, 70)` → `(30, 95)` — сцена стала глубже.
  - `Fence`: `z: 4→5`, `xFrom/xTo: ±6.5→±10` (число столбов пересчитывается автоматически от spacing).
  - `Barn.placeOnSurface`: `(5.0,-1.0)` → `(10.5,-5.0)` — амбар теперь заметно дальше и глубже в тёмной половине, не виден крупным планом с общего плана.
  - `waypoints` (start/land/walkTo) пересчитаны так, чтобы: (а) прыжок через забор стал слегка длиннее (дистанция ×~1.5), (б) путь `land→walkTo` до амбара стал заметно длиннее (дистанция ×~2.3) — теперь `start:(-4.0,7.0)`, `land:(2.4,3.6)`, `walkTo:(8.5,-3.5)`.
  - Деревья/трава/фоновые облака/owl/cat — координаты раздвинуты пропорционально под новый масштаб (чисто декоративная перестановка, без изменения логики).
- `src/core/camera.js` — камера **всё ещё статична** (раздел 4 не реализован), но позиция пересчитана под более широкий забор: `(0,7,16)/lookAt(0,2.2,0)` → `(0,9,21)/lookAt(0,2.6,-1)`, иначе края нового забора (±10 по X) обрезались бы кадром.
- `src/game/SheepAnimator.js` — так как `land→walkTo` стал вдвое длиннее по факту лерпа позиций за фиксированное время, длительности пересчитаны, чтобы скорость движения читалась естественно, а не рывком:
  - `WALK_DURATION`: 1.3 → 2.6 сек.
  - `jumpDuration` (в `release()`): база/разброс `0.65+chargeT*0.35` → `0.85+chargeT*0.46`.
  - `jumpHeight` и остальные тайминги (`LAND_DURATION`, `YAWN_DURATION`, `FADE_DURATION`, `MAX_CHARGE`) не трогались — раздел ТЗ этого не требовал, и они не завязаны на расстояние впрямую.
- Полигональные бюджеты объектов нигде не менялись — только позиции/масштаб композиции и связанные с расстоянием тайминги, как и требовал раздел 2 ревизии.

Проверено в браузере (`npm run dev`, `window.__debug` + `forceRender()` по методике CLAUDE.md): общий план показывает обе половины с воздухом вокруг объектов, полный цикл прыжка (charge→jump→land→walk→yawn→fade) отработал без ошибок в консоли, овца приземляется/доходит ровно до заданных waypoints, окно амбара зажигается, следующая овца встаёт в очередь.

## Важно при продолжении (пункт 4 — camera state machine)

- Расстояния и позиции из пункта 2 теперь финальные (см. выше) — на них можно опираться при проектировании траекторий камеры для всех 5 состояний, менять их заново не нужно.
- Сейчас камера полностью статична (`src/core/camera.js`, `camera.position.set(0,9,21)`, `lookAt(0,2.6,-1)` фиксирован). State machine нужно писать с нуля. `main.js` тянет `camera` пока только для raycasting NPC (`tryTapNpc`) и `resize` — точка интеграции понятна, там же появится вызов апдейта камеры каждый кадр в `tick()`.
- Для `JUMP_CINEMATIC` (вид сбоку на прыжок) стоит опираться на `forwardHint` из `SheepAnimator` (уже считает направление `start→land`) — вид "сбоку от траектории" получается поворотом на 90° от этого вектора.
- Для кувырка овцы в прыжке (доп. часть пункта 4/раздел 5.1) понадобится вращать `sheep.body`/`sheep.group` вокруг оси, перпендикулярной направлению прыжка, синхронно с `_updateJump` в `SheepAnimator.js` — сейчас там вращения тела нет вообще, только сквош/стретч по `scale`.
- Пункт 3 (свет строго сбоку, three-quarter) стоит сделать перед или вместе с пунктом 4, а не после — за это отвечают `SUN_BASE_DIR`/`SUN_ANGLE_START/END` в `src/game/SessionColorCurve.js`, независимые от камеры, так что порядок не критичен, но проще свести оба визуальных ревью в одну сессию тестирования.
- Проверять по методике из `CLAUDE.md` → «Как проверять изменения» (headless Chrome не рендерит rAF в неактивной вкладке — гонять `update(dt)` вручную через `window.__debug`, скриншотить после `forceRender()`).
